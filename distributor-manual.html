1. Device Summary

This manual describes the current delivered configuration only: one proportional valve output, EV1. EV2 is not used, digital outputs are not installed, and no external analog input is required by the integration.

The CVP5C is a CANopen proportional valve controller. In this configuration the CANopen master sends one EV1 current reference, reads the EV1 measured current and supply feedback, monitors EV1 fault flags, and uses SDO only for commissioning/configuration.

What PDO and SDO Mean

PDO means Process Data Object. PDOs are the cyclic or event-driven real-time messages used while the machine is running. Use PDOs for current command, current feedback, voltage feedback, and error bytes.

SDO means Service Data Object. SDOs are request/response messages used to read or write object dictionary entries. Use SDOs for configuration, commissioning, diagnostics, calibration, mapping, saving parameters, and restoring defaults.

Normal control should use RPDO1. Do not use SDO writes as the real-time current command mechanism.

2. Scope

This document describes the device communication interface only. It is intended for distributors and developers who need to build their own control interface without depending on the Galileo Engineering GUI.

The device behaves as a CANopen slave. A master can command EV1 by RPDO, monitor EV1 current and errors by TPDO, and configure persistent parameters by SDO.

The included Windows setup executable is an optional commissioning and diagnostic tool. It is not required by a custom controller once the integrator implements the CANopen messages described here.

3. Quick Start

  1. Connect the device to a powered CAN bus with correct termination.
  2. Use 11-bit CAN identifiers. Default communication is Node-ID 10 and bitrate 250000 bit/s.
  3. Wait for heartbeat on 0x700 + Node-ID. Boot-up is data byte 00.
  4. Put the node in Operational state with NMT frame ID 0x000, data 01 NN, where NN is the Node-ID.
  5. Send current references with RPDO1 on 0x200 + Node-ID.
  6. Read actual EV1 current and supply feedback from TPDO1 on 0x180 + Node-ID.
  7. Read the EV1 fault byte from TPDO2 on 0x280 + Node-ID.
Example for Node-ID 10:
Start node:      CAN ID 000h  DATA 01 0A
Command EV1:     CAN ID 20Ah  DATA rr rr 00 00
Read analog PDO: CAN ID 18Ah  DATA EV1_hi EV1_lo 00 00 Vext_hi Vext_lo Vsupply_hi Vsupply_lo
Read errors:     CAN ID 28Ah  DATA EV1_error 00 00

The current Galileo utility converts a requested current in mA to the raw command value using the active valve settings:

max_raw = (2 ^ resolution_bits) - 1
if current_mA <= 0:
    raw = 0
else:
    raw = round((current_mA - offset_mA) * max_raw / (max_current_mA - offset_mA))
    raw = clamp(raw, 0, max_raw)

For direct controller development, the master may either implement this conversion or command the raw reference expected by the configured resolution. Typical resolution is 8 to 16 bits.

RPDO3 digital command is not used because this configuration has no digital outputs.

Recommended Commissioning Checks

  1. Read identity 0x1018 and firmware 0x2107:06/07.
  2. Read EV1 settings from 0x2102.
  3. Verify producer heartbeat at 0x1017.
  4. Start the node using NMT and check TPDO1 reception.
  5. Send a low EV1 current command first and confirm measured current feedback.
  6. Monitor TPDO2 byte 0 continuously while commanding EV1.
Write persistent settings only during commissioning or maintenance. After changing EEPROM-backed parameters, allow time for storage and verify by reading the same object back.

8. Procedures

Set and Save Producer Heartbeat

  1. Write 0x1017:00 as UNSIGNED16, value in milliseconds.
  2. Write ASCII save to 0x1010:01 using 4-byte expedited SDO download.
  3. Reset communication with NMT command 0x82 if the master needs to restart its supervision timing.

Change Node-ID by Object Dictionary

This method changes the Node-ID by writing object 0x2106:00 through SDO. It is simple and useful when the current Node-ID is already known.

  1. Write the new Node-ID to 0x2106:00 as UNSIGNED8. Valid range is 1..127.
  2. Store parameters by writing ASCII save to 0x1010:01.
  3. Send NMT reset communication 0x82 to the old Node-ID.
  4. Wait for boot-up heartbeat on 0x700 + new Node-ID.
  5. Verify communication by reading 0x1018:01 at the new Node-ID.

Example: change Node-ID from 10 to 11 by SDO

Old Node-ID is 10 (0x0A). New Node-ID is 11 (0x0B). Object 0x2106:00 is UNSIGNED8, so the SDO command byte is 2F.

1) Write 0x2106:00 = 0x0B
TX: CAN ID 60Ah  DLC 8  DATA 2F 06 21 00 0B 00 00 00
RX: CAN ID 58Ah  DLC 8  DATA 60 06 21 00 00 00 00 00

2) Store parameters with ASCII "save" on the old Node-ID
TX: CAN ID 60Ah  DLC 8  DATA 23 10 10 01 73 61 76 65
RX: CAN ID 58Ah  DLC 8  DATA 60 10 10 01 00 00 00 00

3) Reset communication on the old Node-ID
TX: CAN ID 000h  DLC 2  DATA 82 0A

4) Wait for boot-up from the new Node-ID
RX: CAN ID 70Bh  DLC 1  DATA 00

5) Verify identity at the new Node-ID
TX: CAN ID 60Bh  DLC 8  DATA 40 18 10 01 00 00 00 00
RX: CAN ID 58Bh  DLC 8  DATA 43 18 10 01 vv vv vv vv
If no boot-up frame is observed, wait at least 1 second after reset communication and then try the identity read on the new Node-ID.

Change Node-ID by LSS

The device supports LSS slave operation. LSS means Layer Setting Services. If "SSL" is used in informal notes, it refers here to CANopen LSS, not to the TLS/SSL network security protocol.

LSS is useful when the Node-ID must be changed through the standard CANopen LSS procedure. The selective LSS method uses the identity fields from 0x1018: vendor ID, product code, revision number, and serial number.

Use selective LSS only when the device identity is known and unique on the CAN bus. If multiple devices share the same identity fields, disconnect the other devices or use the SDO method on the known Node-ID.

Restore Factory Defaults

  1. Write ASCII load to 0x1011:01. If unsupported by firmware, write value 1 as UNSIGNED32.
  2. Wait approximately 2 seconds for reset/storage handling.
  3. Probe the current Node-ID and the configured default Node-ID.
  4. If the node reverted to default Node-ID, write the desired Node-ID again, store parameters, and reset communication.
  5. Read identity and startup settings to verify the device is responsive.

Run EV1 Valve Mapping

  1. Write value 1 as UNSIGNED16 to 0x2105:03 for EV1.
  2. Poll mapping status: request flag at 0x2105:03 and EV1 mapping flag at 0x2102:16.
  3. Allow up to 45 seconds for completion.
  4. Read the curve from 0x2108:01..101.

The curve contains 101 points, one point per PWM percentage from 0 percent to 100 percent, expressed in mA.

Calibrate Current Reading

  1. Apply a stable current command.
  2. Read actual device current from TPDO1.
  3. Measure the real coil current with an external meter.
  4. Read ConvADC from 0x2102:06.
  5. Calculate new_ConvADC = round(old_ConvADC * measured_mA / device_mA).
  6. Clamp to 1..65535 and write the new value as UNSIGNED16.

9. Diagnostics and Fault Handling

Online Detection

A controller should consider the node online when one of these is true:

  • Heartbeat is received on 0x700 + Node-ID.
  • Expected TPDOs are received from the selected Node-ID.
  • An SDO read of 0x1018:01 succeeds.

The current utility marks a node offline if no heartbeat is observed for at least three heartbeat periods, with a minimum timeout of approximately 2 seconds during normal operation.

EMCY Handling

EMCY frames use 0x080 + Node-ID. When data is present, the current utility reads byte 2 as the CANopen error register and byte 3 as EV1 fault flags. EV2 fault information is not used in this configuration.

Recommended Master Behavior

  • Keep receiving TPDO1 and TPDO2 even while sending current commands.
  • Immediately reduce commanded current to zero if fault bits remain active.
  • Use heartbeat supervision rather than assuming the node remains online after a successful SDO request.
  • After a Node-ID or factory reset operation, reopen SDO communication only after boot-up or after a short reset delay.

Decode TPDO1

def decode_tpdo1(data):
    ev1_ma = int.from_bytes(data[0:2], "big", signed=True)
    vext_mv = int.from_bytes(data[4:6], "big", signed=True)
    vsupply_mv = int.from_bytes(data[6:8], "big", signed=True)
    vext_v = None if vext_mv == -123 else vext_mv / 1000.0
    vsupply_v = None if vsupply_mv == -123 else vsupply_mv / 1000.0
    return ev1_ma, vext_v, vsupply_v

Encode RPDO1 Current Command

def current_ma_to_raw(current_ma, max_current_ma, offset_ma, resolution_bits):
    max_raw = (1 << resolution_bits) - 1
    if current_ma <= 0:
        return 0
    if max_current_ma <= offset_ma:
        return max_raw if current_ma >= max_current_ma else 0
    raw = round((max(0, current_ma - offset_ma) * max_raw) /
                (max_current_ma - offset_ma))
    return max(0, min(raw, max_raw))

def encode_rpdo1(ev1_ma, ev1_settings):
    ev1_raw = current_ma_to_raw(ev1_ma, **ev1_settings)
    return ev1_raw.to_bytes(2, "little") + b"\x00\x00"

Build an SDO Upload Request

def sdo_upload_request(index, subindex):
    return bytes([
        0x40,
        index & 0xFF,
        (index >> 8) & 0xFF,
        subindex,
        0x00, 0x00, 0x00, 0x00,
    ])

# Example: read vendor ID 0x1018:01 from Node-ID 10
can_id = 0x600 + 10
data = sdo_upload_request(0x1018, 1)

Build an SDO Download Request for EV1 Max Current

def sdo_write_u16(node_id, index, subindex, value):
    can_id = 0x600 + node_id
    data = bytes([
        0x2B,
        index & 0xFF,
        (index >> 8) & 0xFF,
        subindex,
